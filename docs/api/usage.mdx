A complete, working integration: obtain the API singleton, fetch the configured public kits, and apply one to a player inside a standard Bukkit listener.

## Full Example

```java ExamplePlugin.java lines
import dev.noah.perplayerkit.API;
import dev.noah.perplayerkit.PublicKit;
import org.bukkit.event.EventHandler;
import org.bukkit.event.Listener;
import org.bukkit.event.player.PlayerJoinEvent;
import org.bukkit.plugin.java.JavaPlugin;

import java.util.List;

public class ExamplePlugin extends JavaPlugin implements Listener {

    @Override
    public void onEnable() {
        getServer().getPluginManager().registerEvents(this, this);
    }

    @EventHandler
    public void onPlayerJoin(PlayerJoinEvent event) {
        API api = API.getInstance();

        List<PublicKit> publicKits = api.getPublicKits();
        if (publicKits.isEmpty()) {
            return;
        }

        api.loadPublicKit(event.getPlayer(), publicKits.get(0));
    }
}
```

## Step by Step

<Steps>
  <Step title="Obtain the API singleton">
    `API.getInstance()` returns the shared object, creating it if needed. Declaring `PerPlayerKit` in your `plugin.yml` `depend` list guarantees the plugin is enabled before your code runs.
  </Step>

  <Step title="Fetch the public kits">
    `api.getPublicKits()` returns a copy of the list, so iterating or modifying it never touches PerPlayerKit's own state.
  </Step>

  <Step title="Load a kit for a player">
    `api.loadPublicKit(player, kit)` applies the kit to an online player's inventory **silently** — no message to the player and no server broadcast.
  </Step>
</Steps>

<Warning>
  Always check `publicKits.isEmpty()` before indexing. If no public kits are configured, `get(0)` throws an `IndexOutOfBoundsException`.
</Warning>

## Selecting a Kit by Id

Indexing by position breaks the moment someone reorders `config.yml`. Match on the kit id instead:

```java
private Optional<PublicKit> kitById(API api, String id) {
    return api.getPublicKits().stream()
            .filter(kit -> kit.id.equalsIgnoreCase(id))
            .findFirst();
}

// usage
kitById(API.getInstance(), "crystal")
        .ifPresent(kit -> API.getInstance().loadPublicKit(player, kit));
```

<Note>
  A kit that appears in `getPublicKits()` is declared in `config.yml`, which does not guarantee an admin ever saved contents to it with `/savepublickit`. Loading an empty kit gives the player an empty inventory — worth handling if your plugin depends on it.
</Note>

## plugin.yml Setup

```yaml plugin.yml
name: ExamplePlugin
version: 1.0
main: com.example.ExamplePlugin
api-version: 1.19
depend:
  - PerPlayerKit
```

<Tip>
  If PerPlayerKit is optional for your plugin, use `softdepend` instead. Your plugin then loads either way — guard your PerPlayerKit code paths with `Bukkit.getPluginManager().isPluginEnabled("PerPlayerKit")` before touching the API.
</Tip>

## Building

Because the dependency is `system`-scoped, the jar is not bundled into your build. Ship your plugin as normal and let Paper resolve PerPlayerKit at runtime through the `depend` entry.

<Warning>
  Re-check your integration on every PerPlayerKit update. The API is explicitly unstable, and a `system`-scoped dependency will not warn you at build time if the server is running a different version than the jar in `lib/`.
</Warning>
