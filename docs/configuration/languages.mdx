Every player-facing string in PerPlayerKit lives in a language file, not in `config.yml`. Fourteen translations ship with the plugin, and you can copy any of them to make your own.

```yaml config.yml
language: "en"
```

<ResponseField name="language" type="string" default="en">
  The language file to load from `plugins/PerPlayerKit/lang/`. Use a bundled code, or any custom code matching a file you added yourself.
</ResponseField>

## Writing Your Own

<Steps>
  <Step title="Copy a bundled file">
    Duplicate `plugins/PerPlayerKit/lang/en.yml` and give it a new code, for example `lang/custom.yml`. Copying rather than editing `en.yml` directly keeps your work safe — bundled files can be rewritten on update.
  </Step>

  <Step title="Edit the strings">
    Change any values you like. Keep the keys and the `{placeholder}` names exactly as they are; only the surrounding text and [MiniMessage](/configuration/messages#minimessage-quick-reference) tags should change.
  </Step>

  <Step title="Point config.yml at it">
    ```yaml config.yml
    language: "custom"
    ```
  </Step>

  <Step title="Restart the server">
    Start up and check the console — a missing key falls back to the built-in English string, and the console tells you which one.
  </Step>
</Steps>

## File Layout

`lang/en.yml` is organized into these sections:

| Section               | Contents                                                                       |
| --------------------- | -------------------------------------------------------------------------------- |
| `prefix`              | The `[Kits]` tag prepended to plugin messages.                                 |
| `motd`                | The join message lines.                                                        |
| `scheduled-broadcast` | The rotating broadcast messages.                                               |
| `broadcast-messages`  | Per-action announcements (kit loaded, gear repaired, …).                       |
| `error`               | Every failure message, including `disabled-in-world`.                          |
| `success`             | Confirmations for saves, shares, deletes, and imports.                         |
| `info`                | Neutral status lines, such as migration progress.                              |
| `command`             | Usage strings shown when a command is used incorrectly.                        |
| `update`              | The new-version notice shown to admins on join.                                |
| `about`               | Output of `/aboutperplayerkit`.                                                |
| `gui`                 | Menu titles and button labels.                                                 |

## Placeholders

Placeholders use `{name}` syntax and are substituted at send time. The most common are `{player}` and `{slot}`; each string's available placeholders are visible in the surrounding context of the bundled file.

<Warning>
  Do not translate the placeholder names themselves. `{player}` is a token the plugin looks for — `{jugador}` renders as literal text.
</Warning>

<Tip>
  MiniMessage reads `<` as the start of a tag. To show a literal angle bracket — like the `<slot>` in a usage string — escape it as `\<slot>`.
</Tip>

## Contributing a Translation

Translations are welcome upstream. Copy `en.yml`, translate the values, and open a pull request on [GitHub](https://github.com/rossnoah/PerPlayerKit) adding it as `lang/<code>.yml`.
