PerPlayerKit splits messaging into two files:

<Columns cols={2}>
  <Card title="config.yml" icon="sliders">
    **Behavior.** Whether a message fires, how often, and which permission is required to see it.
  </Card>

  <Card title="lang/&lt;code&gt;.yml" icon="language">
    **Wording.** The actual text of every message, in [MiniMessage](#minimessage-quick-reference) format.
  </Card>
</Columns>

<Warning>
  Message **text** no longer lives in `config.yml`. If you are following an older guide that tells you to edit `motd.message` or `messages.player-repaired.message` in `config.yml`, edit the [lang file](/configuration/languages) instead — `config.yml` only keeps the toggles.
</Warning>

## MiniMessage Quick Reference

Every player-facing string uses [MiniMessage](https://docs.papermc.io/adventure/minimessage/), which replaces legacy `§` color codes with readable XML-style tags. Tags wrap the text they affect and close with a matching slash tag; they nest and combine freely.

| Tag                                                  | Effect               | Example                                        |
| ---------------------------------------------------- | -------------------- | ---------------------------------------------- |
| `<red>` … `</red>`                                   | Named color          | `<red>Warning!</red>`                          |
| `<aqua>`, `<green>`, `<gray>`, `<gold>`, `<white>` … | Named colors         | `<gold>Gold text</gold>`                       |
| `<color:#RRGGBB>`                                    | Exact RGB color      | `<color:#FF6B35>Custom orange</color:#FF6B35>` |
| `<gradient:#5FD3C2:#17605A>`                         | Gradient across text | `<gradient:#5FD3C2:#17605A>Kits</gradient>`    |
| `<b>`                                                | Bold                 | `<b>Important</b>`                             |
| `<i>`                                                | Italic               | `<i>Hint</i>`                                  |
| `<u>`                                                | Underline            | `<u>/kit</u>`                                  |
| `<st>`                                               | Strikethrough        | `<st>Removed</st>`                             |
| `<reset>`                                            | Clear all formatting | `<reset>Plain text`                            |

**Combined example:**

```xml
<gray>{player} <aqua><b>loaded</b></aqua> a kit</gray>
```

<Note>
  Placeholders in lang files use `{name}` syntax — `{player}`, `{slot}`, and so on. Older versions used `%player%`. If a message renders the literal text `%player%`, it is using the old placeholder style; switch it to `{player}`.
</Note>

## Message of the Day

The MOTD greets players a few seconds after they join, once the join noise has settled.

```yaml config.yml
motd:
  enabled: true
  delay: 5
```

```yaml lang/en.yml
motd:
  message:
    - ""
    - "<gray>   <st>                </st> <aqua><b>Per Player Kits</b><gray> <st>                </st>"
    - ""
    - "         <white>Type <aqua>/kit<white>, <aqua>/k <white>or <aqua>/pk<white> to get started!"
    - ""
```

| Field           | File        | Description                                                                        |
| --------------- | ----------- | ------------------------------------------------------------------------------------ |
| `motd.enabled`  | `config.yml`| Set to `false` to disable the MOTD entirely.                                       |
| `motd.delay`    | `config.yml`| Seconds after joining before the message is sent.                                  |
| `motd.message`  | lang file   | One chat line per list entry. Use `""` for blank spacers. MiniMessage supported.   |

## Scheduled Broadcast

Periodically reminds everyone online that the plugin exists.

```yaml config.yml
scheduled-broadcast:
  enabled: true
  period: 90
```

```yaml lang/en.yml
scheduled-broadcast:
  messages:
    - "<white>Check out public kits with the <aqua>/pk<white> command!"
    - "<white>Want to share a kit? Use the <aqua>/sharekit \\<slot></aqua><white> command!"
    - "<white>Type <aqua>/kit<white>, <aqua>/k <white>or <aqua>/pk<white> to get started!"
```

| Field                             | File         | Description                                        |
| --------------------------------- | ------------ | ---------------------------------------------------- |
| `scheduled-broadcast.enabled`     | `config.yml` | Set to `false` to stop scheduled broadcasts.       |
| `scheduled-broadcast.period`      | `config.yml` | Interval in **seconds** between broadcasts.        |
| `scheduled-broadcast.messages`    | lang file    | The pool of messages to broadcast.                 |

<Note>
  MiniMessage treats `<` as the start of a tag, so a literal `<slot>` in your text must be escaped as `\<slot>` — as in the `/sharekit` example above.
</Note>

## Per-Action Broadcasts

Each kit-related action can announce itself to the server. Toggles and permissions live in `config.yml`; the wording lives under `broadcast-messages` in the lang file.

```yaml config.yml
messages:
  disable-kit-messages: false
  player-repaired:
    enabled: true
    permission: "perplayerkit.kitnotify"
  player-healed:
    enabled: true
    permission: "perplayerkit.kitnotify"
  player-opened-kit-room:
    enabled: true
    permission: "perplayerkit.kitnotify"
  player-loaded-private-kit:
    enabled: true
    permission: "perplayerkit.kitnotify"
  player-loaded-public-kit:
    enabled: true
    permission: "perplayerkit.kitnotify"
  player-loaded-enderchest:
    enabled: true
    permission: "perplayerkit.kitnotify"
  player-copied-kit:
    enabled: true
    permission: "perplayerkit.kitnotify"
  player-copied-ec:
    enabled: true
    permission: "perplayerkit.kitnotify"
  player-regeared:
    enabled: true
    permission: "perplayerkit.kitnotify"
```

```yaml lang/en.yml
broadcast-messages:
  player-repaired: "<gray>{player} repaired their gear</gray>"
  player-healed: "<gray>{player} healed themselves</gray>"
  player-opened-kit-room: "<gray>{player} opened the Kit Room</gray>"
  player-loaded-private-kit: "<gray>{player} loaded a kit</gray>"
  player-loaded-public-kit: "<gray>{player} loaded a public kit</gray>"
  player-loaded-enderchest: "<gray>{player} loaded an ender chest.</gray>"
  player-copied-kit: "<gray>{player} copied a kit</gray>"
  player-copied-ec: "<gray>{player} copied an ender chest</gray>"
  player-regeared: "<gray>{player} regeared</gray>"
```

### Fields

<ResponseField name="disable-kit-messages" type="boolean" default="false">
  **Global off switch.** Set to `true` to silence every action broadcast regardless of individual `enabled` values, the `broadcast-kit-messages` feature flag, or player permissions. The fastest way to get zero chat noise from the plugin.
</ResponseField>

<ResponseField name="[action].enabled" type="boolean" default="true">
  Whether this specific broadcast fires. Set to `false` to suppress one action while leaving the rest active.
</ResponseField>

<ResponseField name="[action].permission" type="string" default="perplayerkit.kitnotify">
  Only players holding this permission see the broadcast. The default node is granted to everyone by default, so all online players see messages unless you explicitly deny the node — or point this at a more restrictive permission of your own.
</ResponseField>

### Available Actions

| Key                         | Fires when…                                     |
| --------------------------- | ----------------------------------------------- |
| `player-repaired`           | A player uses the repair command or GUI button. |
| `player-healed`             | A player uses the heal command.                 |
| `player-opened-kit-room`    | A player opens the Kit Room GUI.                |
| `player-loaded-private-kit` | A player loads one of their own kits.           |
| `player-loaded-public-kit`  | A player loads a public kit.                    |
| `player-loaded-enderchest`  | A player loads a saved enderchest.              |
| `player-copied-kit`         | A player copies another player's kit.           |
| `player-copied-ec`          | A player copies another player's enderchest.    |
| `player-regeared`           | A player uses `/regear` or `/rg`.               |

### Turning the Noise Down

Three layers can silence a broadcast, from broadest to narrowest:

<Steps titleSize="p">
  <Step title="messages.disable-kit-messages: true">
    Kills every action broadcast at once, overriding everything below.
  </Step>

  <Step title="The feature flags">
    [`broadcast-kit-messages`](/configuration/feature-flags) covers kit and enderchest loads; `broadcast-on-player-action` covers the rest.
  </Step>

  <Step title="Per-action enabled and permission">
    Turn off exactly one action, or gate it behind a permission only staff hold.
  </Step>
</Steps>

## Other Message Settings

<ResponseField name="use-display-name" type="boolean" default="false">
  When `true`, `{player}` renders the player's display name — including nicknames set by other plugins — instead of their account name.
</ResponseField>

The plugin prefix (`prefix`), the disabled-world message (`error.disabled-in-world`), and every command response also live in the lang file. See [Languages & lang files](/configuration/languages) for the full layout.
