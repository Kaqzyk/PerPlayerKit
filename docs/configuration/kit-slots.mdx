Every player gets nine kit slots and nine enderchest slots by default. The `max-kits` option changes that limit for both at once.

```yaml config.yml
# Number of kit slots each player has. Applies to both kits and enderchest kits.
max-kits: 9
```

<ResponseField name="max-kits" type="integer" default="9">
  Number of kit slots per player, applied identically to kits and enderchest kits. Valid range is **1–99**; values outside the range are clamped rather than rejected.
</ResponseField>

## What Changes When You Raise It

<Columns cols={2}>
  <Card title="The /kit menu paginates" icon="table-layout">
    The classic single-page menu holds nine kits. Above that, the GUI splits into pages of nine with previous and next buttons in the bottom corners.
  </Card>

  <Card title="Shortcut commands are generated" icon="terminal">
    `/k10`–`/k<max>` and `/ec10`–`/ec<max>` are registered automatically at startup, with the same permissions as the built-in slots.
  </Card>
</Columns>

Slots 1–9 are declared statically in `plugin.yml`. Anything above 9 is registered at runtime, so those commands only exist while `max-kits` is above 9. They are also always reachable in fully-qualified form, which is useful if another plugin claims the same label:

```bash
/k12
/perplayerkit:k12   # same command, unambiguous
```

## Things to Know Before Changing It

<Warning>
  Changing `max-kits` requires a **full server restart**. A reload will not register or unregister the dynamic shortcut commands.
</Warning>

<AccordionGroup>
  <Accordion title="Lowering the limit hides kits — it does not delete them" icon="eye-slash">
    If a player has a kit in slot 15 and you drop `max-kits` to 9, that kit becomes unreachable but stays in the database. Raise the limit again and it reappears untouched.

    [`/purgeitem`](/guides/purge-items) is the exception: it always scans all 99 possible slots regardless of the current setting, so a banned item cannot hide in a slot you turned off.
  </Accordion>

  <Accordion title="Networks must agree on the value" icon="server">
    If multiple servers share one database, set the same `max-kits` on all of them. Otherwise a player's kit saved in slot 12 on one server simply will not exist on another.
  </Accordion>

  <Accordion title="More slots means more stored data" icon="database">
    Each slot is a serialized inventory. Raising the cap to 99 gives every player up to 198 storable inventories (kits plus enderchests). This is rarely a problem, but it is worth knowing if you run YAML or SQLite storage with a very large player base.
  </Accordion>
</AccordionGroup>

## Example

Give players 18 kits — two pages in the menu:

```yaml config.yml
max-kits: 18
```

After restarting, players can use `/k1` through `/k18`, `/ec1` through `/ec18`, and page through both sets in the `/kit` GUI.
