`rekit-on-kill` re-equips the player who lands the killing blow. By default it reloads whatever kit they last used, which keeps a fight moving without a trip to `/kit`. On FFA-style servers you often want the opposite: every kill should hand the killer a fixed, server-defined loadout. The `kits` map does that, down to individual WorldGuard regions.

```yaml config.yml
feature:
  rekit-on-kill:
    enabled: false
    world-whitelist: []
    world-blacklist: []
    kits:
      "ffa": "kit1"
      "ffa:sword_arena":
        kit: "sword"
```

## Options

<ResponseField name="enabled" type="boolean" default="false">
  Turns the feature on. Everything else in this block is ignored while this is `false`.
</ResponseField>

<ResponseField name="world-whitelist" type="list of string">
  World names where rekit-on-kill is allowed. If this list is non-empty, the feature works **only** in these worlds and the blacklist is ignored entirely.
</ResponseField>

<ResponseField name="world-blacklist" type="list of string">
  World names where rekit-on-kill is disabled. Only consulted when `world-whitelist` is empty.
</ResponseField>

<ResponseField name="kits" type="map">
  Optional map of worlds and WorldGuard regions to public kit ids. When an entry matches the killer's location, they receive that public kit instead of their last used kit.
</ResponseField>

The killer also needs the `perplayerkit.rekitonkill` permission, which `perplayerkit.use` grants by default.

## World Filtering

Filtering is evaluated against the **killer's** current world, in this order:

<Steps>
  <Step title="Check the whitelist">
    If `world-whitelist` contains one or more world names, rekit-on-kill **only** activates in those worlds. The blacklist is ignored entirely.
  </Step>

  <Step title="Check the blacklist">
    If `world-whitelist` is empty but `world-blacklist` has entries, rekit-on-kill activates **everywhere except** the listed worlds.
  </Step>

  <Step title="Allow all worlds">
    If both lists are empty, rekit-on-kill activates in **every world**.
  </Step>
</Steps>

<Tabs>
  <Tab title="Arena worlds only">
    ```yaml config.yml
    feature:
      rekit-on-kill:
        enabled: true
        world-whitelist:
          - "pvp_arena"
          - "duel_world"
        world-blacklist: []
    ```
  </Tab>

  <Tab title="Everywhere except spawn">
    ```yaml config.yml
    feature:
      rekit-on-kill:
        enabled: true
        world-whitelist: []
        world-blacklist:
          - "spawn"
          - "lobby"
    ```
  </Tab>

  <Tab title="Every world">
    ```yaml config.yml
    feature:
      rekit-on-kill:
        enabled: true
        world-whitelist: []
        world-blacklist: []
    ```
  </Tab>
</Tabs>

## Giving a Specific Public Kit

Each key in `kits` is either a world or a region inside a world:

| Key form              | Matches                                                                   |
| --------------------- | ------------------------------------------------------------------------- |
| `"<world>"`           | Every kill in that world.                                                 |
| `"<world>:<region>"`  | Kills where the killer stands inside that WorldGuard region in that world. |

Each value names a **public kit id** — the key under the [`publickits`](/guides/public-kits) section, such as `kit1`, not the kit's display name. Both a shorthand and an expanded form are accepted:

```yaml config.yml
kits:
  "ffa": "kit1"        # shorthand: key maps straight to the kit id
  "ffa:sword_arena":   # expanded form
    kit: "sword"
```

<Warning>
  The referenced kit must have contents saved with `/savepublickit <id>`. An entry pointing at a kit with no saved contents is skipped with a console warning, and the killer receives their last used kit instead.
</Warning>

### Matching Rules

1. Region entries (`"world:region"`) always beat world-wide entries (`"world"`).
2. If the killer is inside several overlapping regions that both have entries, the region with the highest WorldGuard priority wins. Ties break alphabetically by region id.
3. If nothing matches, the killer's last used kit is loaded — the default behavior.
4. World and region names match case-insensitively. Quote your keys; region keys contain a colon and YAML will misread them otherwise.
5. `world-whitelist` / `world-blacklist` run **first**. A kill in a filtered-out world never rekits, even if a `kits` entry matches it.

### Requirements and Behavior

<AccordionGroup>
  <Accordion title="Region entries need WorldGuard" icon="map">
    Region keys require [WorldGuard](https://enginehub.org/worldguard) to be installed. It is an optional soft dependency — everything else in PerPlayerKit works without it.

    If region entries are configured but WorldGuard is absent, a warning is logged at startup and those entries are ignored. World-wide entries keep working.
  </Accordion>

  <Accordion title="These kits are applied silently" icon="volume-xmark">
    Kits given through `rekit-on-kill` produce no chat broadcast and no "kit loaded" message, so kill-heavy FFA gameplay does not spam chat.
  </Accordion>

  <Accordion title="Config changes need a restart" icon="rotate">
    Edits to the `rekit-on-kill` block take effect after a server restart.
  </Accordion>

  <Accordion title="The old boolean form still works" icon="clock-rotate-left">
    Configurations using `rekit-on-kill: true` or `rekit-on-kill: false` continue to work. On update the plugin adds the new keys with default values automatically — no manual migration needed.
  </Accordion>
</AccordionGroup>

## Examples

<Tabs>
  <Tab title="FFA world with a special arena">
    Any kill in `ffa` hands the killer the `diamond` public kit — except inside the WorldGuard region `sword_arena`, where they get `sword`.

    ```yaml config.yml
    feature:
      rekit-on-kill:
        enabled: true
        world-whitelist: []
        world-blacklist: []
        kits:
          "ffa": "diamond"
          "ffa:sword_arena":
            kit: "sword"
    ```
  </Tab>

  <Tab title="One kit per arena world">
    Kills in the listed arenas give a fixed kit; kills anywhere else reload the killer's last used kit.

    ```yaml config.yml
    feature:
      rekit-on-kill:
        enabled: true
        world-whitelist: []
        world-blacklist: []
        kits:
          "nethpot_arena": "nethpot"
          "crystal_arena": "crystal"
    ```
  </Tab>

  <Tab title="Last kit, arenas only">
    No `kits` map at all — killers simply get their own last used kit back, and only inside arena worlds.

    ```yaml config.yml
    feature:
      rekit-on-kill:
        enabled: true
        world-whitelist:
          - "pvp_arena"
        world-blacklist: []
    ```
  </Tab>
</Tabs>
