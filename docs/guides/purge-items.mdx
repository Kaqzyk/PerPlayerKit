When an item turns out to be broken, duplicated, or newly banned, disabling it going forward is not enough — copies are already sitting in players' saved kits. `/purgeitem` removes every occurrence of an item type from stored kits and enderchests.

```bash
/purgeitem <item> <all confirm|player ...>
```

**Permission:** `perplayerkit.admin`. Works in game and from the console.

## Targeting Specific Players

```bash
/purgeitem TNT PlayerOne PlayerTwo
```

Removes the item from every kit and enderchest slot of the listed players. Names or UUIDs both work, and the players do not need to be online.

<Note>
  If any name cannot be resolved, the entire purge is cancelled rather than run on a partial list — so it never silently skips someone whose name you mistyped.
</Note>

## Purging Server-Wide

```bash
/purgeitem TNT all confirm
```

Removes the item from **every** player kit and enderchest entry in the database. Because this touches all stored data, the `confirm` keyword is required; without it the command only prints a warning.

<Warning>
  There is no undo. Take a [backup](/configuration/backups) or a [`/kitdata export playerkits`](/guides/kit-data) snapshot before a server-wide purge.
</Warning>

## What It Reaches

<Columns cols={2}>
  <Card title="Nested containers" icon="box-open">
    Also removed from inside shulker boxes of every color, other container blocks stored as items (chests, barrels, dispensers), and bundles — including containers nested inside bundles.
  </Card>

  <Card title="Every storage backend" icon="database">
    Kits are serialized blobs in all backends, so the purge rewrites each affected entry in place and behaves identically on SQLite, MySQL, PostgreSQL, Redis, and YAML.
  </Card>

  <Card title="All 99 slots" icon="layer-group">
    Every possible kit slot is scanned regardless of the current [`max-kits`](/configuration/kit-slots) value, so an item cannot hide in a slot you have turned off.
  </Card>

  <Card title="Online players' caches" icon="rotate">
    Cached kits of online players are refreshed, so the next `/k1` uses the purged version.
  </Card>
</Columns>

### What It Does Not Touch

| Not affected                | Why / what to do instead                                                          |
| --------------------------- | ----------------------------------------------------------------------------------- |
| Live player inventories     | Only stored kits and enderchests are rewritten. Whatever players are holding stays. |
| The kit room                | Admin-managed — edit it via the [kit room editor](/guides/kit-room-setup).         |
| Public kits                 | Admin-managed — re-save with [`/savepublickit`](/guides/public-kits).              |

## Running the Purge

<Steps>
  <Step title="Snapshot first">
    ```bash
    /kitdata export playerkits before-purge
    ```
  </Step>

  <Step title="Stop the item from coming back">
    Remove it from the kit room and, if you want a hard guarantee, enable [`only-allow-kitroom-items`](/configuration/anti-exploit). Purging without this just means the item returns the next time someone saves a kit containing it.
  </Step>

  <Step title="Test on one player">
    ```bash
    /purgeitem TNT PlayerOne
    ```

    Confirm their kits look right before going wider.
  </Step>

  <Step title="Purge server-wide">
    ```bash
    /purgeitem TNT all confirm
    ```

    The purge runs asynchronously. Progress is logged to the console and a summary — items removed, entries modified, deleted, and scanned — is sent when it finishes.
  </Step>
</Steps>

<Note>
  If removing the item leaves a kit or enderchest completely empty, that entry is deleted rather than kept as an empty kit. Only one purge can run at a time.
</Note>
