Public kits are server-defined loadout presets that any eligible player can browse and load on demand. They suit standardized competitive loadouts, new-player starter sets, and seasonal event kits. Unlike personal kits, public kits are authored by admins and shared with the entire player base through `/publickit`.

## Declare the Kit in config.yml

A public kit is defined by an **id** — the key under `publickits`. That id is what commands and the [rekit-on-kill](/configuration/rekit-on-kill) `kits` map refer to.

```yaml config.yml
publickits:
  kit1:
    name: "Kit 1"
    icon: "DIAMOND_SWORD"
  crystal:
    name: "Crystal PvP"
    icon: "END_CRYSTAL"
```

<ResponseField name="publickits.<id>.name" type="string">
  The label shown in the selection GUI. Accepts [MiniMessage](/configuration/messages#minimessage-quick-reference) tags, for example `"<gold><b>Crystal PvP</b></gold>"`.
</ResponseField>

<ResponseField name="publickits.<id>.icon" type="string">
  The item shown in the menu, as an uppercase [Bukkit Material](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/Material.html) name.
</ResponseField>

<Warning>
  The id is not the display name. `/savepublickit crystal` refers to the key, not to `"Crystal PvP"`.
</Warning>

## Save the Contents

<Steps>
  <Step title="Add the entry to config.yml and restart">
    A kit must be declared in `publickits` before contents can be saved to it.
  </Step>

  <Step title="Equip exactly what the kit should contain">
    Fill your inventory — armor slots, off-hand, and hotbar included. This snapshot becomes the kit.
  </Step>

  <Step title="Run /savepublickit with the id">
    ```bash
    /savepublickit crystal
    ```

    Requires `perplayerkit.admin`. A confirmation message and success sound mean it saved.
  </Step>

  <Step title="Verify as a player">
    Run `/publickit` and load the kit to confirm it contains what you expect.
  </Step>
</Steps>

<Note>
  A kit declared in `config.yml` but never saved with `/savepublickit` appears in the menu with no contents. Anything depending on it — including rekit-on-kill entries — logs a warning and falls back.
</Note>

## Loading a Public Kit

```bash
/publickit
```

Aliases `/pk` and `/premadekit` open the same GUI. Players click the kit they want and it replaces their inventory.

<Tip>
  `perplayerkit.publickit` is required, and it is included in `perplayerkit.use`. To restrict public kits to a specific rank, deny the node by default and grant it to that rank directly.
</Tip>

## Sharing Public Kits Between Servers

`/kitdata export publickits <file>` writes every public kit **and its config entry** to a portable file. On import, missing entries are added to the receiving server's `config.yml` automatically — no hand-editing needed. See [Exporting and importing kit data](/guides/kit-data).
