Admins and staff use a separate set of commands to build the kit room, publish public kits, inspect player inventories for moderation, and manage stored data. These sit behind elevated permissions to keep kit data under operator control.

<Note>
  `kit.admin` is a shorthand permission that grants `perplayerkit.admin`, and `kit.staff` grants `perplayerkit.staff`. Use whichever reads better in your permission plugin.
</Note>

## Staff Commands

Require `perplayerkit.staff`. Use them during moderation or support requests.

| Command                | Description                                                |
| ---------------------- | ------------------------------------------------------------ |
| `/inspectkit <player>` | Open the specified player's kits for inspection.           |
| `/inspectec <player>`  | Open the specified player's enderchest kits for inspection. |

## Admin Commands

Require `perplayerkit.admin`.

| Command                                             | Description                                                                          |
| --------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `/kitroom save`                                     | Save the current kit room contents to storage.                                       |
| `/kitroom load`                                     | Reload the kit room from storage, discarding unsaved edits.                          |
| `/savepublickit <id>`                               | Save your current inventory as the public kit with that id.                          |
| `/purgeitem <item> <all confirm\|player ...>`       | Delete every copy of an item from stored kits and enderchests.                       |
| `/kitdata export <scope> <file>`                    | Export kit data to a portable `.ppk` file.                                           |
| `/kitdata import <file>`                            | Import a `.ppk` file.                                                                |
| `/perplayerkit migrate <source> <destination>`      | Copy all kit data from one storage backend to another.                               |
| `/perplayerkit import kitsx`                        | Import data from the KitsX plugin.                                                   |
| `/perplayerkit about`                               | Show plugin information.                                                             |

<Note>
  `/purgeitem`, `/kitdata`, and `/perplayerkit` all work from the **server console** as well as in game.
</Note>

## Kit Room

```bash
/kitroom save     # persist the current contents to storage
/kitroom load     # discard unsaved edits and reload from storage
```

<Warning>
  `/kitroom` requires a subcommand — it is **not** how you open the editor. Running it bare prints a usage message. To edit the kit room, open `/kit` and click the **Nether Star**.
</Warning>

Inside the editor, shift-right-click the barrier block to save a page. `/kitroom save` is the console-friendly equivalent, useful before an [export](/guides/kit-data). See the [Kit Room guide](/guides/kit-room-setup) for the full workflow.

## Public Kits

```bash
/savepublickit <id>
```

Saves your current inventory as the public kit registered under that id in `config.yml`. The id is the key in the `publickits` section — `kit1` in the default config — not the display name. See [Public kits](/guides/public-kits).

## Storage Migration

```bash
/perplayerkit migrate <source> <destination>
```

Copies all kit data between backends. Valid types: `sqlite`, `mysql`, `postgresql`, `redis`, `yml`. The migration runs asynchronously, so the server stays online, and it **copies** rather than moves — the source is left intact.

```bash
/perplayerkit migrate sqlite mysql
/perplayerkit migrate mysql postgresql
/perplayerkit migrate redis sqlite
```

<Warning>
  Back up your data before migrating, and configure the destination's credentials in `config.yml` first. The full procedure is in the [Storage Migration guide](/guides/storage-migration).
</Warning>

## Importing From KitsX

```bash
/perplayerkit import kitsx
```

Reads KitsX data files placed in the PerPlayerKit plugin folder. The command reports which files it found; if none are present it prints instructions instead of failing silently.
