PerPlayerKit has three ways to move kits between players, each suited to a different situation.

<Columns cols={3}>
  <Card title="Direct share" icon="user">
    One kit, one recipient, click to accept. The everyday case.
  </Card>

  <Card title="Share code" icon="hashtag">
    One kit, many recipients. Post it in chat or Discord.
  </Card>

  <Card title="Account transfer" icon="right-left">
    Every kit you own, moved to a new account.
  </Card>
</Columns>

## Sharing Directly With a Player

```bash
/sharekit <slot> <player>
/shareec  <slot> <player>   # enderchest kits
```

The target receives a chat request with clickable **[ACCEPT]** and **[DECLINE]** buttons. On accept, a snapshot of the shared kit is applied to their current inventory (or enderchest), exactly as if they had redeemed a share code.

| Behavior              | Detail                                                                        |
| --------------------- | ------------------------------------------------------------------------------- |
| Expiry                | Requests expire after **120 seconds**.                                        |
| Replacement           | A newer request to the same player replaces the previous one.                 |
| Buttons               | They run `/shareaccept <id>` and `/sharedecline <id>` under the hood.          |
| Without an id         | With only one pending request, plain `/shareaccept` and `/sharedecline` work.  |

<Warning>
  Accepting **overwrites the recipient's current inventory** with the shared kit — it is applied like loading a kit, not added alongside what they are holding.
</Warning>

## Sharing With a Code

Omit the player to get a code instead. This is the right tool when several people want the same loadout.

```bash
/sharekit <slot>          # prints a share code
/copykit  <code>          # anyone redeems it
```

Codes stay valid for **15 minutes** and can be redeemed by any number of players in that window.

## Transferring Every Kit to a New Account

```bash
/transferkits <player>
```

Sends the target a request to receive **all** of your kits and enderchests at once. On accept, a snapshot of every slot you have is saved into their matching slots.

<Steps>
  <Step title="Log in with both accounts">
    Both the old and the new account need to be online on the same server.
  </Step>

  <Step title="Run the command from the old account">
    ```bash
    /transferkits NewAccountName
    ```
  </Step>

  <Step title="Accept on the new account">
    Click **[ACCEPT]** in chat, or run `/shareaccept`.
  </Step>
</Steps>

What happens on accept:

- Every kit and enderchest slot you have is copied into the recipient's matching slot.
- Slots the recipient already used are **overwritten**.
- Slots you do not have are left untouched on their side.
- Your own kits are not modified — this is a copy, not a move.

<Warning>
  There is no undo. If the receiving account already has kits worth keeping, have them export or note those first — the overwrite is silent and immediate.
</Warning>

## Permissions

| Command                           | Permission                     |
| --------------------------------- | ------------------------------ |
| `/sharekit`                       | `perplayerkit.sharekit`        |
| `/shareec`                        | `perplayerkit.shareenderchest` |
| `/transferkits`                   | `perplayerkit.transferkits`    |
| `/copykit`                        | `perplayerkit.copykit`         |
| `/shareaccept`, `/sharedecline`   | `perplayerkit.copykit`         |

All of these are granted by `perplayerkit.use`. To run a server where kits cannot leave their owner, deny `perplayerkit.sharekit`, `perplayerkit.shareenderchest`, `perplayerkit.transferkits`, and `perplayerkit.copykit` individually.

<Note>
  Shared kits pass through the same [anti-exploit](/configuration/anti-exploit) checks as any other kit. With `only-allow-kitroom-items` enabled, items missing from your kit room do not survive the transfer.
</Note>
